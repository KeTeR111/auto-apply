# hh.ru Авто-отклик — Спецификация проекта
# Этот файл — полный контекст для пересборки скрипта с нуля.

## Что делает скрипт
Автоматически откликается на вакансии на hh.ru через браузер (Playwright).
Поиск → оценка через AI → отклик с сопроводительным → логирование.

## Стек
- Python 3.14, macOS, M4 Pro 24GB RAM
- Playwright (Chromium) — браузерная автоматизация
- Ollama (qwen2.5:14b) — локальная AI модель, совместима с OpenAI API
- Возможность переключения на OpenRouter API через .env
- openai (Python SDK) — клиент для запросов к AI
- python-dotenv — чтение .env
- requests — HTTP запросы

## Архитектура

### Вход на hh.ru (Playwright)
1. Открыть hh.ru/login
2. Клик "Я ищу работу"
3. Клик "Войти"
4. Клик "Почта"
5. Ввести email
6. Клик "Войти с паролем"
7. Ввести пароль
8. Submit
9. Клик "Понятно" (баннер cookies)
10. Сессия сохраняется в папке browser_session/ (persistent context)
11. При повторном запуске — проверяет авторизацию, если активна — не логинится

### Поиск вакансий
- Через URL: hh.ru/search/vacancy?text=...&area=...&experience=...&search_field=name
- Параметр search_field=name — искать только в названии вакансии
- Два прохода по опыту: сначала noExperience, потом between1And3 (настраивается в .env)
- Парсинг результатов: ссылки a[data-qa="serp-item__title"], компания из карточки
- Пагинация через [data-qa="pager-next"]

### Фильтрация (до AI, экономит токены)
- По компании: COMPANY_EXCLUDE в .env (сейчас: сбер, sber)
- По опыту в описании: regex ищет "от 4 лет", "5+ лет" и т.п. — пропускает если > 3 лет
- НЕТ фильтра по названию вакансии — убрали

### Оценка через AI
- Промт: оцени вакансию, верни JSON с полями score, reason, interest, experience
- interest = конкретная задача из вакансии (в дательном падеже), 3-6 слов
- experience = что кандидат делал похожего (из резюме), 8-15 слов
- Банки (кроме Сбера) получают +0.15 к score
- До 3 попыток если AI не вернул interest/experience
- max_tokens=600
- MIN_SCORE по умолчанию 0.65

### Сопроводительное письмо
- Собирается в КОДЕ из шаблона (файл templates.txt), НЕ пишется AI
- AI возвращает только interest и experience
- Если AI вернул cover_letter вместо полей — игнорируется
- Обрезка: interest до 100 символов, experience до 200
- Если interest/experience пустые — отклик без письма
- Приветствие "Здравствуйте" гарантируется кодом

### Текущий шаблон (templates.txt)
Здравствуйте! Меня заинтересовала позиция {title}, особенно {interest}. Это пересекается с моим опытом — {experience}. Буду рад обсудить подробности в личных сообщениях.

### Отклик (3 сценария)
1. Попап с textarea → заполнить сопроводительным → отправить
2. Форма с вопросами → _answer_questionnaire → заполнить → отправить
3. Страница "Резюме доставлено" → клик "Приложить сопроводительное письмо" → попап → заполнить → отправить
- Проверка disabled кнопки перед кликом
- Если кнопка заблокирована — пропуск

### Ответы на вопросы работодателя (_answer_questionnaire)
- Находит все textarea/input на странице
- Для каждого поля через JS ищет текст вопроса рядом
- Типовые ответы по ключевым словам (без AI):
  - Зарплата (зарплат/оклад/ожидани/доход/руки/з-п): сумма по score (120-150к)
  - Формат работы (гибрид/офисн): "Да, готов рассматривать гибридный и офисный форматы работы."
  - Готовность (когда готов/приступить): "Готов приступить сразу."
  - Город: "Москва."
  - Контакты (telegram/мессенджер): "Telegram: @K_E_T_E_R"
  - Уровень SQL: "7 из 10. Уверенно пишу SELECT, JOIN, подзапросы, оконные функции, CTE."
  - Почему ищу работу: "Закончил НИУ МЭИ, ищу позицию в аналитике данных."
  - Чем заинтересовала: "Интересны задачи по аналитике данных, стек совпадает с моим опытом."
  - Аутсорсинг: "Да, такой формат подходит."
  - Python опыт: "Pandas, NumPy, Scikit-learn, XGBoost, Matplotlib."
  - ML опыт: "Около 1.5 лет. В дипломной обучал XGBoost, LightGBM, Random Forest."
  - Инструменты: "SQL (PostgreSQL, DBeaver), Python, Tableau, Excel с макросами."
- Нетиповой вопрос → отправляется AI с резюме
- Если есть тесты (radio, checkbox) → логировать в лог, пропустить вакансию
- Все вопросы + ответы записываются в logs/questions.txt

### Зарплата по score
- score >= 0.85 → 150 000 рублей
- score >= 0.75 → 140 000 рублей
- score >= 0.65 → 130 000 рублей
- else → 120 000 рублей

### Логирование
- Папка logs/ — единственное место для всех данных
- logs/YYYY-MM-DD.log — каждая вакансия (отклик, пропуск, ошибка)
- logs/questions.txt — вопросы работодателей с ответами
- Формат лога:
  ═══════════════════
  [HH:MM:SS] СТАТУС
  ───────────────────
  Вакансия: ...
  Компания: ...
  ID: ...
  URL: ...
  Оценка: ...
  Причина: ...
  Interest: ...
  Experience: ...
  ───────────────────
  Сопровод: ...
- Статусы: ✅ ОТКЛИК, ⏭️ ПРОПУСК (оценка), ⏭️ ПРОПУСК (опыт), 🚫 ФИЛЬТР, ⚠️ ОШИБКА
- НЕТ applied.json — не нужен
- Логи терминала: только stdout, без файла auto_apply.log

### Запуск
- Файл start.sh: активирует venv, создаёт его при первом запуске, запускает скрипт
- Скрипт сам запускает Ollama если она не запущена (только для localhost)
- ./start.sh --visible — с браузером, ./start.sh — headless
- После завершения в --visible режиме: браузер остаётся открытым, "Нажмите Enter"
- Сессия сохраняется в browser_session/

### .env параметры
- HH_EMAIL, HH_PASSWORD — аккаунт hh.ru
- AI_BASE_URL — http://localhost:11434/v1 (Ollama) или https://openrouter.ai/api/v1
- AI_MODEL — qwen2.5:14b или anthropic/claude-sonnet-4-5
- AI_API_KEY — ollama или sk-or-...
- SEARCH_QUERIES — запросы через ;
- AREA — код региона (1=Москва)
- SALARY_FROM — фильтр зарплаты
- COMPANY_EXCLUDE — компании через ;
- EXPERIENCE_PASSES — noExperience;between1And3
- DAILY_LIMIT — 200
- MIN_SCORE — 0.65
- SAVE_COVER_EVERY — 1 (сейчас не используется, логируется всё)
